# Indexing infrastructure

Reference doc for how touatiayoub.com's crawling/indexing pipeline works, what's
verified, and what's still a manual step. Written as part of Commit 8 — keep it
up to date when the sitemap, robots, or SEOHead entity model changes.

## Sitemap

- Generated by `scripts/generate-sitemap.ts` from `src/lib/seo-data.ts` and
  `src/data/blog-articles.ts` — no hardcoded URL lists. Run via
  `npm run generate-sitemap`, wired into `build:full` / `build:seo`.
- **Lastmod strategy**: structural pages (core, service, city, service×city)
  use `CONTENT_LAST_MODIFIED`, a constant bumped **by hand** when that content
  actually changes — not a build timestamp. Blog posts use their real `date`
  field (static articles) or `published_at`/`created_at` (DB posts). This
  matters: a lastmod that says "today" on every deploy regardless of real
  changes is a known anti-pattern Google may learn to ignore.
- **Sitemap index**: not active — 93 URLs is far below the 50,000 protocol
  limit. `scripts/generate-sitemap.ts` has a dormant `toSitemapIndex()`
  function and a warning at 40,000 URLs so migrating is a small step, not a
  rewrite, when the URL count grows (e.g. once `/secteurs/*` and
  `/entreprises/*` ship).
- **Future clusters prepared, not active**: `industryPages()` in the same
  file is fully written but not called in `buildSitemap()` — no live route
  exists for `/secteurs/*` yet. Submitting those URLs now would create the
  same soft-404 pattern `/tarifs` had (Phase 1). Activate by adding
  `...industryPages()` to the array in `buildSitemap()` once the route ships.

## robots.txt

- Generated by `scripts/generate-robots.ts` from `scripts/robots-config.ts` —
  the single place to add/remove a crawler or change a disallow rule.
- Every named crawler group (Googlebot, Bingbot, AI crawlers, etc.) now
  disallows `/admin/`, `/api/`, `/uploads/` — previously only the fallback
  `User-agent: *` group did, meaning named crawlers technically weren't told
  to avoid the admin panel at all (robots.txt groups don't fall back to `*`
  once a more specific match exists).
- AI crawlers (GPTBot, ChatGPT-User, ClaudeBot, Claude-Web, PerplexityBot,
  Google-Extended, CCBot) are explicitly named and allowed — policy default.

## Canonical consistency — FIXED (Aug 2026 SEO audit)

Previously documented here as a known limitation ("prerendering coded but not
running on the Hostinger host" — attributed to missing `libXss.so.1` on that
build host). **That diagnosis was wrong**, and the real fix is now shipped.

Root cause, actually confirmed by running the old pipeline and capturing the
swallowed error: `vite-plugin-prerender` depends on
`@prerenderer/renderer-puppeteer`, which pins `puppeteer@^1.7.0` — a 2019
release bundling Chromium 78. Chromium 78 predates optional chaining /
nullish coalescing (`?.` / `??`, Chrome 80+), which this build's untranspiled
output uses deliberately (see the `build.target` comment in `vite.config.ts`).
So every route hit a hard `SyntaxError` on the very first script tag, the
React root never mounted, and `renderAfterElementExists: "footer"` timed out
at 30s **on every single route**. The plugin's own `.catch()` swallows the
real error and only logs `"Unable to prerender all routes!"` — so this failed
silently, and had likely never actually worked. Verified live in production
before the fix: `curl https://touatiayoub.com/agence-digitale-meknes` (no JS)
returned the **homepage's** `<title>` and canonical, not its own.

**Fix**: `scripts/prerender-static.mjs`, run as a separate step after
`vite build` (wired into `build:prerender` / `build:full` / `build:seo`).
Small, dependency-light script using whatever `puppeteer` is actually
installed (a current version — real Chromium) against a plain Node static
file server; falls back to a system Chrome/Edge install if the bundled
Chromium download is unavailable (`findSystemBrowser()` in that script — this
dev machine's own `puppeteer` Chromium download landed corrupted, so this
path is exercised routinely here, not just theoretical). Writes each route's
fully-rendered HTML to `dist/<route>/index.html` (root `/` → `dist/index.html`
directly). Route list comes from `scripts/prerender-routes.ts`, the same
single source of truth `vite.config.ts` re-exports `buildPrerenderRoutes`
from.

Apache serves these prerendered files directly — `public/.htaccess`'s SPA
fallback only rewrites when `RewriteCond %{REQUEST_FILENAME} !-f`, i.e. when
no real file exists at that path. One knock-on fix was needed:
`DirectorySlash Off` was added to `.htaccess` (see the comment there) because
Apache's default `mod_dir` behavior 301-redirects `/agence-digitale-meknes`
(no trailing slash, but now a real directory) to `/agence-digitale-meknes/`
— a redirect that didn't exist before and that would have conflicted with
every canonical tag, sitemap entry, and internal link (all no-trailing-slash).

Browsers get the same prerendered files and then React hydrates over them
exactly as before — no behavior change for real visitors, only for crawlers
that don't execute JS (Bing, most AI crawlers, link-preview bots).

**Deploy note**: this still isn't meant to run on a stripped build host —
build locally or in CI (anywhere Chrome/Chromium is available) and deploy the
resulting `dist/` folder. Verified locally: 163/163 routes prerendered,
`npx tsc --noEmit` clean, `validate-indexing` 0 failures, 0 duplicate
`<title>`/`<meta description>` across all 163 pages, 0 canonical mismatches.

Verify after deploying: `curl https://touatiayoub.com/agence-digitale-meknes`
(no JS) and confirm `<title>`/canonical match that URL, not `/`.

## Hreflang — current state and future plan

Locale (`fr`/`ar`) is a client-side toggle stored in `localStorage`
(`I18nProvider.tsx`) — there is exactly one URL per page regardless of
language. The `fr-MA` / `ar-MA` / `x-default` hreflang tags `SEOHead.tsx`
emits are therefore self-referencing (all three point at the same URL) —
valid, but not what hreflang is designed to do (link *distinct* URLs per
language).

Prepared, not implemented: `SEOHead`'s `hreflangAlternates` prop lets any page
add real alternate-locale entries once they exist, without touching the
hreflang logic itself:

```tsx
<SEOHead
  ...
  hreflangAlternates={{ en: "/en/entreprises" }}
/>
```

This will matter once the Path C secondary-market track (`/entreprises/*`)
gets its English mirror (`/en/entreprises/*`, per Phase 2 §10 scalability
plan) — at that point pass the mirror's path here rather than redesigning
anything.

## Search Console readiness

**Not yet verified — no fabricated placeholder inserted.** Two ways to verify,
pick one:

1. **DNS TXT record (recommended for this setup)** — no code change needed.
   Add the TXT record Search Console gives you to the domain's DNS at
   whatever registrar/host manages `touatiayoub.com`. Cleanest option since it
   doesn't touch the app at all and survives any future rendering-strategy
   change.
2. **HTML meta tag** — if DNS access isn't available, Search Console will give
   you a `<meta name="google-site-verification" content="...">` tag. Add it to
   `index.html`'s `<head>`, next to the other meta tags, once you have the
   real value from your Search Console account — I can't generate this value,
   it's tied to your Google account.

Once verified: submit `https://touatiayoub.com/sitemap.xml` under Sitemaps,
and check the Coverage report after the next deploy for the dead blog URLs
fixed in Commit 6 disappearing from "Excluded."

## Crawl budget recommendations

- At 93 URLs, crawl budget isn't a real constraint yet — these are forward
  guardrails, not current fixes.
- `Crawl-delay` is already set per major crawler (Googlebot: 1s, Bingbot: 2s,
  fallback: 5s) — reasonable for current traffic; revisit if the server ever
  shows crawl-induced load.
- When `/secteurs/*` (5 pages) and `/entreprises/*` (~15 pages) ship, re-run
  `npm run validate-indexing` and recheck the URL-count warning threshold —
  still far from 50,000, just a sanity check habit to keep.
- Avoid future faceted/parameter URL explosion (e.g. `?sort=`, `?page=`) —
  none exist today; if pagination or filtering is added to `/blog` or
  `/realisations`, canonicalize to the unparameterized URL rather than letting
  every parameter combination get its own crawlable URL.
- Tier-3 city pages (Safi, El Jadida, Nador, Béni Mellal — see Phase 2 §05)
  already carry lower `priority` values in the sitemap; no further budget
  action needed there.

## Automated validation

`npm run validate-indexing` (`scripts/validate-indexing.ts`) checks, and exits
non-zero on failure so it can gate a build:
1. No duplicate sitemap URLs.
2. No sitemap URL under a robots.txt-disallowed path.
3. `BASE_URL` consistency between the sitemap and robots configs.
4. Every sitemap URL matches a known, live route pattern.
5. URL count within the sitemap protocol limit.

Wired into both `build:full` and `build:seo`.
